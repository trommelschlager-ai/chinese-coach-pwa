# Безопасность проекта «Мой китайский»

## Для владельца репозитория

1. Защитите аккаунт GitHub двухфакторной аутентификацией (предпочтительно приложением-аутентификатором или ключом доступа / passkey). Не передавайте коды восстановления.
2. В GitHub → Settings → Rules → Rulesets установите правило для ветки `main`: **Restrict deletions** и **Block force pushes**. Проверьте, что подключённый инструмент для обновлений по-прежнему может добавлять обычные коммиты. Не вводите обязательное одобрение чужим ревьюером без необходимости.
3. Проверяйте список Collaborators и разрешения подключённых GitHub Apps. Права записи выдавайте только тем, кому действительно доверяете.
4. Никогда не размещайте пароли, токены, приватные ключи или секреты оплаты в `index.html`, `sw.js`, `assets/` и других публичных файлах. Клиентский JavaScript всегда доступен посетителям.
5. Храните резервные копии и историю коммитов. Регулярно проверяйте Security → Dependabot alerts / Secret scanning, если доступны.
6. В GitHub Pages содержимое сайта публично даже при размещении исходников в приватном репозитории на поддерживаемом тарифе. Перевод репозитория в приватный на бесплатном тарифе может снять сайт с публикации.

## Сообщения об уязвимостях

Не публикуйте найденные пароли, токены и приватные данные в открытых Issues. Используйте приватное сообщение владельцу или механизм приватного сообщения об уязвимости (Private vulnerability reporting), если он включён.

Эти правила снижают риски случайной утечки и несанкционированных изменений, но не могут запретить копирование HTML, CSS, JavaScript и ресурсов публичного приложения.
